# Worked examples and reference library

## 3D character animation on video editor panels

[0xwhrrari's “No After Effects. Just Clawd.”](https://x.com/0xwhrrari/status/2112166940081004693) was recreated locally as a 12-second Blender/HTML 3D animation of Clawd moving on and interacting with video editor panels, with synthesized sound. Use the [recipe and bundled source](clawd-motion-studio.md) to regenerate the accepted remake or adapt its mascot-to-UI contacts, floating panels and beat-linked comp changes. The recipe retains the guide/PDF links, installation, exact timing, camera repairs and measured verification limits. This is an optional worked example, not Animation Creator's default story or toolchain.

## Optional worked example

[Bin Liu's stacked Whop/Sonnet comparison](https://x.com/liu8in/status/2104976353485631856) links [Andrian's original](https://x.com/az_andrian/status/2104495114534133847) and HyperFrames. The paired clip uses oversized cropped typography, full-frame color changes, a central numeral expanded into a repeated field, and a sparse logo ending. These are useful motion mechanisms to adapt when they serve the brief. Its retained "Post-employment" wording illustrates why a new brand needs a scene-by-scene meaning pass. The author's observation that Sonnet copied well but improvised little describes this attempt; it does not establish general model performance or change the user's chosen model. The clip's duration, palette, numerals, and stacked comparison layout are example details.

For a tightly matched product-motion reference, study [dawood46's reference rebuild and full prompt](https://x.com/notdwd/status/2104401208958230764). The reusable method is to choose strong motion first, inventory the real product inputs, then map the source shot by shot: framing, object paths, easing, directional blur, cuts, and sound peaks. State which motion relationships should match and replace the source's brand, interface, and copy with verified product material. The posted prompt asks for a few stills at named frames before full rendering; review a transition in playback too. When fidelity is the goal, play source and result synchronized side by side to compare timing and movement. Its 12-second scene plan, exact frame numbers, palette, HTML `seek(t)` renderer, and claimed time and cost are details of that example, not defaults or verified results for another project.

For an explicitly requested frame-locked remake, consult the [full example prompt and workflow](https://x.com/notdwd/status/2103959830423859595) as a reference. Probe the source's actual frame rate, dimensions, duration, and audio; extract frames and make a shot table with exact cut frames. Measure key object bounds and paths, cursor tip, camera moves, on-screen text, typing cadence, and audio cues from the reference frames instead of relying on a prose description alone. Build a renderer that can seek to a requested frame, then compare source and output at shot boundaries, key poses, and transition frames. Review a synchronized side-by-side video after encoding, fix visible drift, and report remaining differences with frame numbers. Use properly licensed replacement music and voice when the source audio is not supplied for reuse. The post's HTML architecture, worker count, numeric tolerance, and audio targets are example choices, not defaults for other pieces.

For the printed jellyfish look, read [references/riso-example.md](riso-example.md) and adapt [assets/jellyfish.html](../assets/jellyfish.html). This is a verified five-second Canvas example, not a universal template. Do not load or copy it for unrelated styles.

For a lyric-driven, hand-painted music video, study [NotinReality's finished example](https://x.com/other__reality/status/2102514581684052169), its [source and storyboard](https://github.com/JohnHeibel/PDoomVideo), and the separate [p5.js + p5.brush starter](https://github.com/JohnHeibel/ClaudeAnimationBase). The author supplied lyrics and audio, reviewed a basic first pass, then asked Claude for brushstrokes, more interesting scenes, and transitions between them. The source divides the song into chapters, paints each frame from song time, and uses contact sheets before MP4 export.

In the finished video, short lyric scenes keep changing location and visual premise while the same orange character, researcher, P(doom) meter, illustrated texture, and caption band make them feel like one piece. The lyrics become concrete visual gags and actions rather than a sequence of decorated text cards. Recurring stage curtains and ensemble shots let the later scenes build toward a finale and title-card ending. For a similar brief, plan both **variety at the line level** and **continuity across the song**: track the recurring cast and props, give each line one readable action, carry transitions between scenes, and reserve a distinct ending. Reuse the **audio → lyric/beat timing → shot storyboard → scene passes → rendered review** method; use the user's own character, story, and properly usable audio. The example's look, model, effort, and turnaround are references, not defaults or expected results.

## Reference library

For coordinated text, SVG, UI, or camera-like animation sequences, consult [GSAP's official documentation](https://gsap.com/docs/v3/) and inspect relevant examples in its [showcase](https://gsap.com/showcase/). Use its timelines when they simplify choreography; for video export, pause and seek the timeline through the existing deterministic render contract. The [engine guidance](motion-craft.md#engine-guidance) links official agent skills. Keep an existing suitable stack and use simpler CSS or Web Animations for isolated effects.

For procedural environments, physical simulations, pixel creatures, or code-authored explainers, browse the [Claude Sonnet 5.5 showcase index](sonnet-55-showcase.md). It links all seven examples in the official thread and separates observed visuals from author claims. Load only examples relevant to the brief; the showcase does not change the user's chosen model or establish general performance.

[HyperFrames](https://github.com/heygen-com/hyperframes) is an optional local HTML-to-MP4 renderer for typography, DOM motion, and timed media. When using it, read its current [composition contract](https://github.com/heygen-com/hyperframes/blob/main/skills/hyperframes-core/SKILL.md) and [CLI guide](https://github.com/heygen-com/hyperframes/blob/main/skills/hyperframes-cli/SKILL.md). Declare composition dimensions and duration, use seekable animation, and let the framework own media playback. Run its composition checks, inspect preview and transition frames, then review a draft encode before final delivery. A passing check establishes technical validity; inspect the resulting motion separately. Keep the existing stack when suitable. Use this renderer within the task's existing delivery authorization; its availability does not require adopting its plugin or broader workflow.

For product launch videos, browse [What Ships](https://whatships.com) by product type and watch one or two relevant originals for hook, pacing, product footage, and transition ideas. For a repo-led teaser, the [Brag repository](https://github.com/latent-spaces/brag) contains a `brag-slim` skill whose useful pattern is to inspect the real project, storyboard its entry → action → result, then render and review with local tools. Use that pattern when it fits; do not install or invoke the repository's service-backed full workflow for this skill.

For compact loading or agent-status motion, inspect [Circle Loaders](https://circleloaders.dominikakissi.com) as standalone SVG examples and adapt one only if it communicates the state clearly. For browser motion that needs coordinated timelines, scroll response, SVG drawing or morphing, springs, or direct manipulation, [Anime.js](https://animejs.com) is an optional free library. Keep the existing stack and avoid adding it for a simple CSS or Web Animations effect.

When a brief resembles an interactive HTML animation, use the [100 HTML examples library](opus-html-gallery.md) to find a matching motion mechanism. The library records Eric's favorites, and the index links each live piece, its exact original prompt, and its source. Read only the relevant entries, inspect the running example and source, then adapt the technique to the user's subject and delivery format. The gallery includes static layouts, games, and tools as well as animations; do not treat every entry as a motion reference or copy its visual style by default.

For code-native interactive art, particles, flow fields, shaders, or canvas/WebGL sketches, read the [p5.js guide](p5js/guide.md) and only the technique references it points to. The [seed-and-parameter viewer](../assets/p5js/viewer.html) is an optional starting asset. Keep an existing stack when integrating into a product.

For pencil handwriting that writes on, a photo painted stroke by stroke, or a short clip repainted as a living painting, read the [p5.brush paint guide](p5-paint/guide.md), its [worked flows](p5-paint/flows.md), and relevant [gotchas](p5-paint/gotchas.md). The runnable renderer and sketches live in [scripts/p5-paint](../scripts/p5-paint). This is an offline PNG/MP4 workflow with pinned dependencies and render cost per frame; use it when that handmade treatment is the brief, not as a default for all animation.
