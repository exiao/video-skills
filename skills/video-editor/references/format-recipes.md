# Verified recipes for recurring video formats

Use when repeating an accepted founder clip, interview, product demo, or other established format. Keep its recipe and presets in the project alongside the source and editable timeline. The general editing skill should route to those records rather than accumulating company-specific grades, captions, or tool settings.

## Establish the first working edit

Complete one representative edit through the actual configured editor or rendering workflow. Preserve the successful commands or tool calls, required assets, settings, and manual steps. Resolve failures and inspect the rendered result before labeling the procedure verified. A plausible plan or successful tool response is insufficient.

Capture only the decisions needed to reproduce that format:

| Part | What the project recipe records |
|---|---|
| Inputs | Expected camera, screen, and audio sources; media IDs; frame rates; sync reference; required presets |
| Assembly | Clip-selection criteria, camera-switching rules, screen-overlay timing, and transition behavior |
| Picture | Color treatment by source type, crop/reframe rules, and any exceptions for UI readability |
| Text | Caption style and safe placement, title treatment, and how optional hook variants replace the opening |
| Audio | Cleanup method, source-to-timeline mapping, mixing and loudness targets, and resync checks |
| Delivery | Editable project location, export preset, dimensions, caption outputs, and acceptance example |

Omit irrelevant rows. Record tested tool/editor versions and any remaining manual steps. Reference real presets and an inspected example rather than inventing universal settings. Camera footage and screen captures may need different treatment; do not apply a camera grade to UI by default.

If cleanup requires exporting audio and reimporting it, preserve its source start, sample rate, duration, and alignment reference. Check for introduced delay or duration changes and verify sync near the beginning, middle, and end. Use external cleanup only within the job's upload authorization; otherwise use available local processing or identify the missing step.

## Reuse and repair

On a new edit, check that the inputs and required capabilities fit the recipe, then run its known steps. Keep content choices and source ranges in the EDL, with the recipe holding repeated production settings. A changed editor, media type, or preset warrants an affected-step preview before batch execution. Preserve prior cuts.

Inspect the first new output before multiplying variants. Verify that it retains the actual product action, readable text, correct captions and sync, and the accepted format. Fix a failed step and update its project recipe from the working result. Keep final creative judgment and publishing authorization with the existing parent workflow.

## Illustrative application

A recurring demo combines a founder camera and a screen recording. Its verified recipe identifies the two sources, screen entrance/exit treatment, separate camera and UI color settings, caption preset, and export settings. Each episode supplies its own statement and source ranges. The recipe standardizes execution without forcing identical stories or camera cuts.

## Source and limits

[Mason Warner's Slash workflow video](https://x.com/masonwarner/status/2110403718604853440), 8:01–9:22, describes format-specific editing instructions refined by manually walking an agent through the first edit. This reference adapts that procedure; the clip does not supply his presets, skill files, or an independently reproducible editing benchmark. No particular editor, model, or MCP implementation is required.
